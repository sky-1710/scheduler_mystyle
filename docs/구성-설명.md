# 구성 설명 (개발자용)

앱을 수정하거나 데이터를 직접 다루고 싶을 때 참고하는 문서입니다.

## 전체 구조

- **의존성 없는 단일 `index.html`** — CSS, HTML, JavaScript(바닐라)가 한 파일에 있습니다.
- 순서: `<style>` (테마 변수 → 뷰별 CSS) → HTML (뷰 6개 + 모달들) → `<script>` (상태 → 유틸 → 뷰 렌더러 → 모달 로직 → 백업 → INIT)
- 렌더링은 전부 `render()` 하나로 시작합니다: 현재 탭(`currentView`)에 맞는 `renderMonth / renderWeek / renderDay / renderHabit / renderStats / renderTodo`를 호출하고 사이드바를 갱신합니다.

## 데이터 모델

### events — 일정과 할일 (하나의 배열)
```js
{
  id: "고유id",
  title: "제목",
  isTodo: true,          // true=할일(체크리스트), false=일정
  date: "2026-07-05",    // 시작일 (반복이면 반복 시작일)
  endDate: "2026-07-09", // 기간 일정의 종료일 ('' = 하루짜리). 반복·범위 할일과 조합 불가, D-day 기준
  time: "14:00", endTime: "15:00",
  scope: null,           // null=특정 날짜 할일, "week"=주간 할일, "month"=월간 할일 (date가 소속 기준)
  repeat: "none|daily|everyN|weekly|monthly|yearly",
  repeatN: 3,            // everyN일 때 주기(일)
  repeatEnd: "2026-12-31",
  notifyBefore: 10,      // 분 단위, 0=없음
  color: "#5C6BC0",
  priority: "high|normal|low",
  accuracy: 90,          // 정확도 %, null 가능
  categoryId: "카테고리id 또는 null",
  desc: "메모",
  completed: false,      // 비반복 할일의 완료 (반복 할일은 todoDone 사용)
  completedAt: "2026-07-05",  // 완료 날짜 (보관함 판정용)
}
```

### 나머지 상태
| 변수 | 형태 | 설명 |
|---|---|---|
| `blocks` | `{ "날짜": { "HH:MM": id } }` | 10분 타임블록 (시각화용). 값은 event 또는 habit의 id |
| `blockMin` | `{ "날짜": { "HH:MM": 1~10 } }` | 블록 안에 실제 채워진 분 (없으면 10 = 꽉 참). 타이머가 1분씩 올리고, 그리드에서 부분 채움으로 표시 |
| `timeLog` | `{ "날짜": { id: 분 } }` | **1분 단위 시간 장부** — 모든 합계·통계의 원천. 수동 색칠 ±10분, 타이머는 실제 경과 분만큼 적립 |
| `dayTasks` | `{ "날짜": [eventId] }` | "가져오기"로 그 날에 붙인 할일 |
| `todoDone` | `{ "날짜": [eventId] }` | **반복 할일**의 날짜별 완료 |
| `dayGoals` / `dayMemos` | `{ "날짜": "텍스트" }` | 일간 GOAL / MEMO |
| `dayBad` / `dayRatings` | `{ "날짜": "텍스트" }` / `{ "날짜": 1~10 }` | TODAY'S REVIEW — 반성 기록 / 하루 별점 |
| `sleepLog` | `{ "날짜": { wake, sleep } }` | 기상·취침 시각 (HH:MM). 수면 시간 = 어제 sleep → 오늘 wake |
| `dayImages` | `{ "날짜": [dataURL] }` | 메모 사진 (JPEG, 최대 1000px 압축) |
| `habits` | `[{ id, name, color, categoryId }]` | 습관 목록 |
| `habitChecks` | `{ "날짜": [habitId] }` | 습관 날짜별 체크 |
| `categories` | `[{ id, name, color, parentId, weeklyGoalH }]` | 중첩 카테고리 (parentId로 트리) |

### 핵심 헬퍼
- `isTodoDone(ev, ds)` / `setTodoDone(ev, ds, val)` — 완료는 반드시 이 함수로 읽고 씁니다 (반복이면 todoDone, 아니면 ev.completed + completedAt)
- `evMatchesDate(ev, ds)` — 반복 규칙 포함해 그 날짜에 표시되는지
- `findPaintable(id)` — 블록 id → `{title, color}` (event/habit 공용)
- `catById / catChildren / catPath / topCatOf / isUnderCat` — 카테고리 트리 탐색
- `getDayTaskList(ds)` — 일간 TO DO 목록 (할일만, 미완료→우선순위→시간 정렬)

  "dayGoals": {...}, "dayMemos": {...},

- 스냅샷: `schedule_backup_YYYY-MM-DD.json`, 7일마다 생성, 최근 8개 유지, **사진 제외**.

## 저장 흐름

```
변경 발생 → saveEvents()
             ├─ persistLocal()      : localStorage 반영 (사진 제외)
             └─ autoSyncToFile()    : 폴더 연결 시 schedule_data.json 저장
                                      + 주 1회 스냅샷 + 오래된 스냅샷 정리
사진 변경  → saveImages()           : IndexedDB 반영 (+ autoSyncToFile)
```

시작 시(`INIT`): `loadEvents()`(localStorage) → `pruneOrphans()`(고아 참조 정리) → `loadImages()`(IDB, 비동기) → `restoreDataDir()`(폴더 재연결 + 파일에서 최신 데이터 로드).

- **다중 탭 동기화**: `storage` 이벤트 리스너가 다른 탭의 `sched_*` 키 변경을 감지하면 `loadEvents() + render()`로 자동 갱신한다.
- **저장 실패 보호**: `persistLocal()`은 try/catch로 감싸져 있어 localStorage 실패(용량 초과 등) 시 토스트로 알린다.

## 주요 동작 흐름

### 타임블록 색칠
`renderDay()`가 24×6 그리드 생성 → `pointerdown/move`로 `applyPaint()` (paintTaskId 색으로 blocks 갱신) → `pointerup`에서 저장 + 라벨 다시 그림. `paintTaskId`는 TO DO/HABIT 줄 클릭으로 설정되고 `'ERASE'`면 지우개.

### 실시간 기록
`recording = {id}` 상태를 localStorage에 저장. 1초 시계(`updateClock`)가 `recordTick()`을 호출해 현재 10분 블록을 자동 색칠(블록이 바뀔 때만 저장). 자정 감지 시 알림 재예약 + 리렌더도 이 시계에서 처리.

### 통계 집계
`statsPeriod`(week/month/year)에 따라 날짜 배열을 만들고 공용 빌더로 조립:
`blocksMinutes(dates)` → 시간 / `todoStatsFor` · `habitAvgPct` → 완료율 / `catMinutesRollup` → 카테고리 롤업(하위→상위 합산) / `buildStackedChart` → 스택 막대 / 연간은 히트맵을 직접 그림.

## 수정할 때 주의점

1. **완료 상태를 `ev.completed`로 직접 읽지 말 것** — 반복 할일이 깨집니다. 항상 `isTodoDone/setTodoDone` 사용.
2. **새 데이터 종류를 추가하면 7곳에 등록**: `loadEvents`, `persistLocalUnsafe`, 백업 payload 3곳(autoSyncToFile·downloadBtn·backupBeforeImport), 가져오기 복원 2곳(importFile·loadFromDataDir). 등록 여부는 [`tests/persisttest.js`](../tests/persisttest.js)가 자동 검증한다 (DATASETS 목록에도 이름 추가).
3. **event/habit 삭제 시** blocks·dayTasks·todoDone·habitChecks에서 참조 제거 (기존 삭제 핸들러 참고). 빠뜨려도 `pruneOrphans()`가 다음 시작 때 정리하긴 합니다.
4. 날짜 문자열은 항상 `ymd()`로 만든 `YYYY-MM-DD` 로컬 기준입니다. `toISOString()` 사용 금지(UTC라 하루 밀릴 수 있음).
5. **범위 할일(scope)** 은 날짜 기반 화면에서 제외해야 합니다 — 날짜별 목록을 만들 땐 `!ev.scope && evMatchesDate(...)` 패턴을 유지하세요 (`getEventsForDate`, `dayTodoList`, `getDayTaskList`, D-day 참고). 사이드바 표시는 `renderScopeTodos()`가 담당합니다.
